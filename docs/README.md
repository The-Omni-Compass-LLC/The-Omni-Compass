### Hierarchy of evidence and claims

1. **Canonical source and version:** identify the precise engine fingerprint and commit before comparing any results.
2. **Mathematics and contracts:** identify proved statements, assumptions, modeled approximations, and unproved extensions.
3. **Runtime mechanism:** trace observe → decide → admit → actuate → verify → restore; distinguish a simulation from a live actuator.
4. **Measurements:** keep physical meters, live software results, and simulations in separate evidence classes.
5. **Benchmark verdicts:** disclose Native and Omni raw values, direction, uncertainty, resource tradeoffs, and adverse outcomes; never treat a 0.5% practical floor as exact equality.
6. **Financial implications:** present only costs measured or priced inside an explicit boundary; unresolved bills remain unresolved.
7. **Board and IP claims:** link every material claim to its source, caveats, ownership terms, and independent verification status.

**Release discipline:** changes to the control mechanism, scoring, versioning, or claims must pass the repository's verification gates before promotion. Historical receipts remain immutable. A document or dashboard generated by a script must be changed through its canonical generator, not hand-edited.
